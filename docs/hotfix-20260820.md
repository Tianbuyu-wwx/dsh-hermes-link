# Hotfix 2026-08-20 — dsh web 拉不起 / MCP bridge 不通的修复记录

## 症状

1. `npx @file:`deepseek-ai/dsh` web`（错误语法）和 `npx @deepseek-ai/dsh web` 都启动失败：
   - 第一轮：`ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/dsh-skill-filesystem'`
   - 第二轮：`ReferenceError: harness is not defined`（hermes-oneshot-arbitrate/index.mjs:124）
2. Hermes MCP 里 `dsh-bridge` 两个工具不可用：`dispatch_task` 空 schema、`get_dispatch` 报 unknown tool。

## 根因（逐层）

| # | 层 | 根因 | 修法 |
|---|---|---|---|
| 1 | 依赖解析 | 三个 hermes-* 包的 `index.mjs` 直接 `import '@deepseek-ai/dsh-skill-filesystem'`，但 package.json 无 `dependencies` 声明，包目录里也无 `node_modules`。Node ESM 沿符号链接目标路径（`E:\项目\dsh-hermes\packages\hermes-*\`）向上找 node_modules → 找不到 | 在三个包目录建 `node_modules/@deepseek-ai/dsh-skill-filesystem` junction → npx 缓存中的 `@deepseek-ai/dsh-skill-filesystem`（版本 0.1.0-rc.8）。oneshot 额外 junction 了 `dsh-tools`（defineTool 需要）。**注意：这是本地临时桥接；正式修法是把依赖写进各包 package.json + 在 repo 里 pnpm install** |
| 2 | API 写法 | `harness.defineTool(...)` / `harness.registerTool(ctx, tool)` —— `harness` 全局在 dsh cordis loader 中不存在（25KB 源码 0 处出现）。dsh 自家 bundle 的标准写法是 `import { defineTool } from '@deepseek-ai/dsh-tools'` + `ctx.tools.register(tool)` | 改 hermes-oneshot-arbitrate：inject 加 `'tools'`；`ctx.tools.defineTool` → `defineTool`（import 进来）；`harness.registerTool(ctx, tool)` → `ctx.tools.register(tool)` |
| 3 | schema 格式 | `parameters: { type:'object', properties:{...}, required:[...] }`（标准 JSON Schema）不符合 dsh `parameterSchemaSpecToJsonSchema` 的 flat shape（key 直接是参数名，无外层 type）→ `UNSUPPORTED_SCHEMA` | parameters 改为 flat shape，`required` 用字段级 `required: true` |
| 4 | 路由 kind | `webServer.register({ kind:'http', ... })` —— dsh-host-webserver 只认 `kind: 'exact'`/`'prefix'`；`'http'` 被三目表达式归入 prefixes 表，且 handler 签名是 `(req, res)`，返回对象不会被写进 res → 客户端超时 | 两个路由改 `kind: 'exact'`；handler 改 `(req, res) => send(res, httpReply(...))`，新增 `send()` helper |
| 5 | POST body | `readAllStream(req.body || req.rawBody || '')` —— node:http 的 `req.body`/`req.rawBody` 都是 undefined → 恒空 → "missing body" | 直接传 `req`（IncomingMessage 本身就是 Readable 流，readAllStream 支持） |
| 6 | audit 路径 | `dshHome()` win32 分支返回 `%APPDATA%\dsh`，dsh 真家是 `~/.dsh` | 改为统一 `homedir()/.dsh`（DSH_HOME 优先不变） |
| 7 | MCP inputSchema | `tools/list` 里 `dispatch_task.inputSchema: { $ref: './dispatch-spec.schema.json' }` —— 相对 $ref 客户端解析不了 → Hermes 端空参数 | 内联展开（引用导入的 schema 对象：type/required/additionalProperties/properties） |

## 遗留

- **v0.2 未做**：真实 sub-agent spawn（`subagents.start(...)`）、SQLite 持久幂等表、tokenMeter.measure、ajv schema、tools/restrict。当前 `dispatch_task` 仍为 audit-only。
- **junction 是临时桥**：`E:\项目\dsh-hermes\packages\hermes-{foundation,oneshot-arbitrate,dispatch-bridge}\node_modules\@deepseek-ai\` 下的 junction 指向 npx 缓存。npx 缓存被清（`npm cache clean` 或 npx 新 hash 目录）后需重建；正式做法是各包 package.json 声明依赖。
- **ui-skin-nahida orphan patch**：`~/.dsh/profiles/web/cordis.patch.yml` 中 `- id: ui-skin-nahida` 在 bundle 树中不存在（dump-config 报 "entry not found"），软警告不致命，可清理。
- **旧 audit 文件**：`%APPDATA%\dsh\dispatch-audit.jsonl`（修复前落错位置）可删。
- 当前 Hermes 会话的工具 schema 是启动时注册的旧 stdio 版；**新会话**才会用 HTTP 版（带完整参数 schema）。
